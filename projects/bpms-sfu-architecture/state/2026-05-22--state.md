## Load-bearing technical facts

### SFU ownership

**Owns:** OBG ingest, lane alignment, bins selection, filter-bank synth/analysis,
band gain, band Doppler, RF interfacing, timing, management, debug.
**Does NOT own:** beam gain, beam Doppler, beam delay — those belong to DCU.
Flag any boundary-crossing proposal immediately. Authoritative table: `arch/fad/FAD.md` §1.2.

### PS software scope boundary

Repo covers PL RTL only. PS software out of scope: TLE/SGP4 propagation, mgmt
protocol stack (REST/SNMP per OI-S07), Ethernet GEM driver, NMS provisioning.
PL blocks `mgmt` and `band_doppler` are PL components with defined PS↔PL
interfaces; PS counterparts live in a separate repo (TBD). ADR-0003 triggered
at FAD §11 authoring.

**Refined 2026-05-21 (§4.2.4):** Clock-device control plane is two-path, both
PS-originated:
- Si5394: PS → hardened I²C → device.
- LMK04821 + LMX2594 ×2: PS → AXI4-Lite → PL SPI bridge → device, driven by
  bittware `rfx_clock_setup.elf`.

### Module Spec / Micro-Architecture split (ADR-0005, pending Gastón)

- **Architect** delivers MS (`arch/modules/<module>.md`): black-box external
  contract. Gate: G4a (`design_ready`). Content: ports, interfaces, clock
  domains, registers, operation, performance, errors, test hooks, system
  constraints, refmodel pointer.
- **Designer** delivers uArch (`rtl/<module>/uarch.md`): internal implementation
  (FSMs, pipeline, FIFOs, .sv decomposition). Gate: G4b.
- Granularity: 23 MS files covering ~28 RTL instances.

### Module inventory — 23 MS files, ~28 RTL instances (consolidated 2026-05-01)

- DL/UL identical contract → one parameterized MS with `DIRECTION` param, two instances.
- `obg_rx` + `obg_tx` → `obg_link` (single bidirectional MS; 4 Aurora lanes, full-duplex).
- `bins_sel`, `band_gain`, `band_doppler`, `band_rms_det` → each one MS, two instances.
- `filter_bank_synth` / `filter_bank_analysis` → two separate MSs (different vendor IP cores).

### Key structural decisions

- **rf_port_sel (FAD-DEC-08):** digital PL-fabric mux between `band_doppler` and
  `rfdc_wrap` — NOT an analog switch.
- **band_rms_det (FAD-DEC-09):** passive tap. DL: post-`band_gain_dl`.
  UL: post-`band_doppler_ul` / pre-`band_gain_ul`. Dashed arrow in diagrams.

- **CDC ownership (FAD-DEC-07):** mechanism policy in FAD §4.5; per-block protocol

- **UTC-apply vs Local Autonomous:** `utc_apply_engine` handles shadow→live commits.
  `tle_compute` writes **directly** to `band_doppler` live NCO at 1PPS — bypasses
  engine. ADR-0004 must trigger before the first UTC-scheduled-parameter MS.

### Sub-band architecture and beam capacity

Two parallel chains per direction (Sub-band A + B), 1,024 MHz native / ~819.2 MHz
usable each. Independent filter bank + `band_gain` + `band_doppler` per chain.
Beam slots: 48 per sub-band (16/lane × 3 lanes), 96 total per SFU. RF BW limit
(1,600 MHz ÷ BW) binding at ≥5 MHz. One MS per function; §2.2 diagram shows
hardware parallelism via parallel lanes.

### FAD §4 — clocking and reset architecture (v0.7 baseline 2026-05-21)

**Four clock domains:**

| Clock | ASIC-sat | FPGA-sat | Source | Scales? |
|---|---|---|---|---|
| `clk_rfdc_axis` | 256 MHz | 262.144 MHz | LMX2594 → RFdc ADC tile PLL → BUFG_GT | yes |
| `clk_dsp` | 341.333 MHz | 349.525 MHz | MMCM M=4 D=3 from `clk_rfdc_axis` | yes |
| `clk_aurora_user` | 300 MHz | 300 MHz | Aurora 64B/66B IP user_clk (uw=64, 32/33 valid) | **no** |
| `clk_mgmt` | 100 MHz `[ADR-0003]` | (same) | PS `pl_clk0` → BUFG | **no** |

**Clock-pair relationships (4×4 matrix, §4.5.2):**

|  | aurora | dsp | rfdc | mgmt |
|---|---|---|---|---|
| **aurora** | — | async | no path | async |
| **dsp**    | async | — | sync-derived | async |
| **rfdc**   | no path | sync-derived | — | async |
| **mgmt**   | async | async | async | — |

1PPS is an asynchronous edge event, not a clock domain. Enters `clk_mgmt`
(UTC counter) and `clk_dsp` (1PPS-aligned Doppler load) via two-flop + edge
detector + glitch filter in `pps_capture`.

**Reset architecture (R1–R7, §4.4.1):**

- R1: Synchronous reset, active-low, everywhere downstream of bridge.
- R2: Reset bridge on every domain entry (async assert / sync deassert; the
  only place async flop primitives appear).
- R3: Control-path only (FSMs, counters, sticky flags, CDC FIFO pointers,
  config valid bits).
- R4: Datapath no-reset (preserves SRL/DSP-slice/CE packing).
- R5: Config-register data flops have explicit INIT (per field, safe inert
  default, rationale in MS); module-level enable bit IS reset.
- R6: IP-internal resets follow IP convention (Aurora, RFdc, MMCM, QSPI).
- R7: One reset per clock domain (default).

**Four fabric resets:** `rst_mgmt_n`, `rst_dsp_ctrl_n`, `rst_aurora_n`,
`rst_rfdc_n`. See FAD §4.4.2 for full inventory.

**Sat-switch (§4.6, thin pointer to ADR-0010):**

- Planned re-commissioning event; live switching not supported.
- Aurora link preserved (Si5394 OUT0/OUT1 multisynth N held constant per HW
  Guide §8.2.1 per-output MultiSynth architecture).
- Si5394 OUT3, LMK04821, and both LMX2594 devices ARE reprogrammed at
  sat-switch (previous "Si5394 untouched" framing corrected).
- `clk_mgmt` and `clk_aurora_user` uninterrupted; `clk_rfdc_axis` and `clk_dsp`
  re-lock at new frequencies.
- In-flight `obg_link` FIFO bins are discarded by design.
- Affected modules with sat-rate-dependent CSRs: `band_doppler_dl/ul`,
  `cw_beacon`, `pps_capture`, possibly `band_rms_det_dl/ul`.

**CDC inventory (§4.5.3):** 13 crossings (CDC-01 through CDC-13), compressed
to enumeration + mechanism category + owner MS. Per-crossing protocol detail
moves to owner MS. Bidirectionally consistent with `report_cdc` at sign-off.

**MTS not used (FAD-DEC-19):** AMS_SYSREF, PL_SYSREF, PL_CLK_ADC/DAC are
unused; HW Guide §8.2.7 MTS clock requirements do not apply.

## Key learnings & principles

- **Reset architecture: two-axis discipline.** Inside any clock domain, fabric
  resets are synchronous (R1). The async-assert / sync-deassert pattern lives
  **only** at the reset-bridge primitive at each domain entry (R2). Separation
  enables SRL/DSP-slice/CE packing while still handling power-up and async
  reset sources.

- **Config register pattern: INIT per flop + module-level enable.** Each CSR
  data flop has an explicit INIT value (safe inert default, specified per
  field with rationale in MS). Module readiness signalled by a module-level
  enable bit (which IS reset), not per-field valid bits.

- **MultiSynth-per-output is load-bearing for Aurora preservation.** Si5394
  per-output dividers mean retuning OUT3 at sat-switch leaves OUT0/OUT1 (MGT
  REFCLKs) glitchless. This makes Option A (Si5394 + LMK + LMX reprogram at
  sat-switch) viable.

- **PS owns clock-device writes; PL-side `clock_ctrl` coordinates.** At
  power-on, PS drives device programming autonomously; clock_ctrl observes
  lock status. At sat-switch / mode-switch, clock_ctrl and PS cooperate via
  mailbox/event.

- **CDC table is sign-off-grade enumeration only.** FAD §4.5.3 lists every
  crossing with mechanism category and owner MS. Per-signal protocol detail
  lives in the owner MS. Bidirectionally consistent with `report_cdc` at
  sign-off.

- **FAD vs ADR vs MS scope discipline.** FAD = architectural commitments that
  cross module boundaries. ADR = decision rationale + sequenced state machines
  + alternatives considered. MS = per-block external contract. When in doubt:
  "does every consumer need to know?" → FAD; "could this have gone another
  way?" → ADR; "is this internal to one block?" → MS.

- **Anti-laundering discipline.** Every factual claim cites a source document
  §, an ADR, or an `[ASSUMPTION]` / `[INFERRED]` marker with expiry trigger.
  Architect-judgement content should be marked explicitly so it can be
  revisited.

- **CDC methodology split.** FAD §4.5 holds project-wide CDC policy
  (approved mechanism list, clock-pair relationships, intentional crossings).
  Vivado `report_cdc` handles per-flop enumeration at CI. Per-spec CDC
  mechanism sections are redundant.

- **SFU/DCU boundary is load-bearing.** FAD §1.2 ownership table is
  authoritative; any boundary-crossing proposal requires an ADR with
  system-level citation.

- **Lean framework over documentation sprawl.** 5-document framework
  (FAD, MS, ICD, ADR, RTM) chosen over 15-document extended proposal.

- **Citation tiers.** Three tiers: cited, `[INFERRED from §]`,
  `[ASSUMPTION: text, expiry trigger]`.
